## 具体缺口及改进

- 默认层级拥挤：全部Agent按钮常驻且最多74DIP可滚动，名称也常驻。改为正文占主层、紧凑“给谁”选择（含全部自定义标签），名称/项目合并同一可选区域；不从快照删除标签，也保留管理路径。
- 低屏高时整个main `overflow:auto`，正文min110、展开项目和错误可能把动作带出首屏。改为稳定header/footer与独立正文/可选区滚动；保证最小可写面积、错误与保存状态可见，不靠缩小文字。
- 当前平台共享CSS，没有Windows专属Segoe UI/中文回退与系统背景边缘适配。下一增量统一层级与布局，Mac/Win分别字体、轻微圆角/边界/键位，主题只在输入窗作用，不改已认可的绳纸配色。Windows在Mac的演示标为平台样式模拟，不称真机截图。
- 当前原子草稿只在正常关闭/受控退出时提交；输入途中没有逐步落盘IPC，也无render-process-gone恢复处理。不能把已保存快照恢复称为未保存内容的崩溃恢复。下一增量应给新建草稿有界防抖原子保存和状态，明确崩溃恢复边界；编辑恢复需与原便签分离，不自动覆盖正文或破坏取消语义。
- IME已有事件保护，仍需组合开始/结束、229、Esc与平台提交/换行回归；不把合成事件包装成系统中文IME。busy增加同步操作闩，防同一事件批次重复，失败后恢复可重试并把焦点还到正文。
- Tab/读屏当前靠label、aria-pressed、alert等基础标记；需实测合理Tab序、选择器名称、展开状态、编辑/新建标题、错误关联/保存状态live，以及关闭后不强拉别的App焦点。

## 准备的轻量方案

约530DIP面板：小标题与关闭 → 明确正文标签/大文本区 → 单一Agent归属选择 +“名称与项目”展开 → 可见保存/错误状态 → 平台键位提示与单个主动作。新建显示“挂上”，编辑显示“保存修改/取消编辑”；复杂迁移确认仅在需要时出现。查找/标签管理为次级临时入口。长正文内部滚动，展开可选项不覆盖正文、错误和主要动作。背景实色、克制边界与阴影，不增加模糊材质依赖或持续动画。

实现验收顺序：先准确旧版真实Mac浅/深整体截图与绑定；在新隔离增量产出浅深/可选展开/长文/错误/低屏高/高DPI，并明确Windows模拟；然后保护核心草稿与提交流程的纯逻辑/协议/异常退出，独立审阅必要增量。系统IME、真实热键/跨App焦点和Windows物理矩阵独立保留。新截图和方案不能继承0.0.15包通过或改写它的固定哈希。
